# 文件级目录设计文档

## 1 文档说明
**说明**：本文档详细描述智能烟感系统的核心文件结构，包含文件名、路径、功能说明，确保文件组织清晰、职责明确。

## 2 通用规范要求
- **单一功能原则**：一个文件仅实现一个核心功能（如"设备注册入参DTO"单独建文件，不合并）
- **命名规范**：
  - 后端：大驼峰命名（如UserRegisterDTO.java）
  - 前端：小驼峰+类型后缀（如userRegister.dto.ts）
- **分层对齐**：文件目录与文件夹分层严格对齐，文件名明确体现功能（避免"Util.java"等模糊命名）

## 5 关键文件功能说明

### 5.1 后端关键文件

| 文件名 | 核心功能 | 设计原则体现 | 输入/输出示例 |
| :--- | :--- | :--- | :--- |
| ProtocolAdapter.java | 定义协议适配的统一接口，支持多种传感器协议 | 开闭原则、依赖倒置 | 输入：原始协议数据 → 输出：标准化传感器数据 |
| DeviceRegisterDTO.java | 定义设备注册操作的入参结构，包含核心字段校验规则 | 单一职责 | 输入字段：deviceId、deviceType、deviceName等 |
| DeviceService.java | 定义设备管理的业务逻辑接口，包括注册、绑定、查询等 | 依赖倒置、单一职责 | 输入：DeviceRegisterDTO → 输出：DeviceVO |
| AlarmProcessor.java | 定义报警处理的统一接口，负责报警检测和处理 | 依赖倒置、单一职责 | 输入：SensorData → 输出：List<Alarm> |
| NotificationChannel.java | 定义通知发送的统一接口，支持多种通知渠道 | 开闭原则、依赖倒置 | 输入：接收人、内容 → 输出：NotificationResult |

### 5.2 前端关键文件

| 文件名 | 核心功能 | 设计原则体现 | 输入/输出示例 |
| :--- | :--- | :--- | :--- |
| SensorList.vue | 设备列表页面，展示传感器设备信息 | 单一职责、高内聚 | 输入：查询条件 → 输出：设备列表展示 |
| AlarmMonitor.vue | 报警监控页面，实时展示报警信息 | 单一职责、高内聚 | 输入：实时报警数据 → 输出：报警信息展示 |
| deviceApi.js | 封装设备管理相关后端接口请求 | 高内聚、低耦合 | 输入：业务参数 → 输出：Promise<后端响应数据> |
