# 错误记录规范

## 1. 目的

本规范旨在建立统一的错误记录标准，确保开发团队能够高效地记录、跟踪和解决系统开发过程中遇到的各种错误和问题，提高开发效率和代码质量。

## 2. 适用范围

本规范适用于智能烟感系统开发过程中所有阶段（需求分析、设计、开发、测试、部署、维护）遇到的错误和问题。

## 3. 错误分类

### 3.1 按技术领域分类

- **后端错误**：后端服务、API接口、数据库等相关错误
- **前端错误**：UI界面、前端组件、数据交互等相关错误
- **系统集成错误**：系统间集成、第三方服务对接等相关错误
- **部署运维错误**：系统部署、环境配置、性能监控等相关错误

### 3.2 按严重程度分类

- **致命错误（Critical）**：导致系统崩溃、数据丢失或核心功能完全不可用的错误
- **严重错误（High）**：导致重要功能不可用或影响大量用户的错误
- **中等错误（Medium）**：导致部分功能不可用或影响少数用户的错误
- **轻微错误（Low）**：不影响系统功能，仅影响用户体验或代码质量的错误

## 4. 错误记录格式

每个错误记录必须包含以下五个主要部分：

### 4.1 错误描述

- **错误标题**：简洁明了地描述错误的核心问题
- **错误现象**：详细描述错误发生时的具体表现
- **发生环境**：记录错误发生的系统环境信息
  - 操作系统版本
  - 浏览器类型和版本（前端错误）
  - 设备型号和操作系统（移动应用错误）
  - 网络环境
  - 系统版本号
- **复现步骤**：详细列出能够复现错误的操作步骤
  ```
  1. 打开系统登录页面
  2. 输入正确的用户名和错误的密码
  3. 点击登录按钮
  4. 观察系统反应
  ```
- **错误截图**：如有必要，添加错误发生时的截图或录屏

### 4.2 错误分析

- **错误定位**：确定错误发生的具体位置
  - 文件路径
  - 函数/方法名
  - 行号
- **错误日志**：记录相关的错误日志信息
- **可能原因**：分析可能导致错误的原因
  - 代码逻辑错误
  - 数据格式错误
  - 环境配置问题
  - 依赖库问题
  - 网络问题
- **影响范围**：评估错误对系统功能的影响范围
  - 影响的功能模块
  - 影响的用户群体
  - 影响的业务流程

### 4.3 解决方案

- **解决思路**：描述解决错误的整体思路和方法
- **具体步骤**：详细列出实施解决方案的步骤
- **代码修改**：记录相关的代码修改内容
  ```javascript
  // 错误代码
  function calculateTotal(price, quantity) {
    return price * quantity;
  }
  
  // 修复后的代码
  function calculateTotal(price, quantity) {
    if (typeof price !== 'number' || typeof quantity !== 'number') {
      return 0;
    }
    return price * quantity;
  }
  ```
- **相关依赖**：记录需要更新或修改的依赖库

### 4.4 验证结果

- **验证方法**：描述验证解决方案有效性的方法
- **验证环境**：记录验证的系统环境信息
- **验证结果**：详细描述验证结果
  - 错误是否复现
  - 功能是否正常工作
  - 性能是否受影响
  - 其他相关功能是否正常
- **测试截图**：如有必要，添加验证后的截图或录屏

### 4.5 相关信息

- **记录人**：记录错误的人员姓名
- **记录时间**：错误记录的时间（格式：YYYY-MM-DD HH:mm:ss）
- **解决人**：解决错误的人员姓名
- **解决时间**：错误解决的时间（格式：YYYY-MM-DD HH:mm:ss）
- **严重程度**：错误的严重程度（致命/严重/中等/轻微）
- **关联任务**：相关的开发任务或需求编号
- **关联文档**：相关的设计文档或规范
- **备注**：其他需要说明的信息

## 5. 文件命名规范

错误记录文件的命名应遵循以下格式：

```
[错误分类]-[错误编号]-[简要描述].md
```

### 5.1 错误分类

使用以下缩写表示错误分类：

- **后端错误**：BE
- **前端错误**：FE
- **系统集成错误**：SI
- **部署运维错误**：DO

### 5.2 错误编号

- 按错误分类分别编号
- 使用三位数字（如：001、002、003...）
- 从001开始递增

### 5.3 简要描述

- 使用中文描述错误的核心问题
- 字数控制在10个汉字以内
- 避免使用特殊字符

### 5.4 示例

- `BE-001-数据库连接超时.md`
- `FE-002-登录页面样式异常.md`
- `SI-003-第三方API调用失败.md`
- `DO-004-服务器部署失败.md`

## 6. 记录流程

1. **发现错误**：开发人员在开发、测试或用户反馈中发现错误
2. **初步评估**：评估错误的严重程度和影响范围
3. **创建记录**：在相应的错误分类目录下创建错误记录文件
4. **填写信息**：按照错误记录格式填写完整的错误信息
5. **分配处理**：将错误分配给相关开发人员处理
6. **实施修复**：开发人员实施解决方案
7. **更新记录**：修复完成后，更新错误记录中的解决方案和验证结果
8. **关闭记录**：验证通过后，关闭错误记录

## 7. 管理与维护

1. **定期回顾**：每周进行一次错误记录回顾，总结经验教训
2. **统计分析**：每月对错误记录进行统计分析，识别常见问题和改进方向
3. **归档管理**：定期归档已解决的错误记录，保持目录结构清晰
4. **规范更新**：根据实际使用情况，定期更新本规范
