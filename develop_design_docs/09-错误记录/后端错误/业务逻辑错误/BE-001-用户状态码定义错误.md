# BE-001-用户状态码定义错误

## 1. 错误描述
- 错误现象：admin用户在登录系统时，即使密码正确且用户状态已设置为启用（status=1），系统仍提示"用户已封禁，请联系管理员"
- 发生环境：
  - 操作系统：Linux Ubuntu
  - 后端版本：若依框架3.9.0
  - 数据库：MySQL
- 复现步骤：
  1. 确保数据库中admin用户的status字段为1
  2. 访问系统登录页面
  3. 输入正确的用户名和密码
  4. 点击登录按钮
  5. 观察到登录失败，提示"用户已封禁"

## 2. 错误分析
- 错误定位：/var/ctt_wkplace/iot/backend/src/main/java/com/ruoyi/common/enums/UserStatus.java
- 可能原因：UserStatus枚举中状态码定义与业务逻辑不符
- 影响范围：
  - 影响的功能模块：用户登录验证
  - 影响的用户群体：所有系统用户
  - 影响的业务流程：用户无法正常登录系统

## 3. 解决方案
- 解决思路：修正UserStatus枚举中的状态码定义，确保正常状态对应正确的数值
- 具体步骤：
  1. 查看UserStatus枚举类的定义
  2. 发现OK状态的code为"0"，DISABLE状态的code为"1"
  3. 修正状态码定义，将OK状态的code改为"1"，DISABLE状态改为"0"
- 代码修改：
  ```java
  // 错误代码
  public enum UserStatus
  {
      OK("0", "正常"), DISABLE("1", "停用"), DELETED("2", "删除");
  }
  
  // 修复后的代码
  public enum UserStatus
  {
      OK("1", "正常"), DISABLE("0", "停用"), DELETED("2", "删除");
  }
  ```

## 4. 验证结果
- 验证方法：重启后端服务后，使用admin用户再次尝试登录
- 验证环境：与错误发生环境相同
- 验证结果：
  - 错误不再复现
  - 用户可以正常登录系统
  - 系统功能正常工作
