# 接口规范文档

## 一、文档说明

目的：规范智能烟感系统前后端交互接口的设计和实现，确保接口的一致性、可用性和可维护性。

适用范围：所有参与智能烟感系统开发的团队成员。

## 二、接口设计原则

### 1. RESTful 设计风格
- 使用 HTTP 方法表示操作类型（GET/POST/PUT/DELETE）
- 使用 URL 表示资源（如：`/api/device/sensor/list`）
- 使用 HTTP 状态码表示响应结果
- 使用 JSON 格式进行数据传输

### 2. 接口命名规范
- URL 使用小写字母和斜杠分隔（如：`/api/device/sensor/list`）
- 保持与现有项目接口命名风格一致
- 避免使用动词（如：`/api/get-sensors` 错误）

### 3. 版本控制
- 暂不使用版本号，保持与现有项目接口风格一致

## 三、请求规范

### 1. 请求方法
| 方法 | 描述 | 幂等性 |
|------|------|--------|
| GET | 获取资源 | 是 |
| POST | 创建资源 | 否 |
| PUT | 更新资源 | 是 |
| DELETE | 删除资源 | 是 |
| PATCH | 部分更新资源 | 是 |

### 2. 请求参数

#### 2.1 查询参数（Query Parameters）
- 用于过滤、排序、分页等操作
- 示例：`/api/sensors?areaId=1&page=1&size=10`

#### 2.2 路径参数（Path Parameters）
- 用于标识特定资源
- 示例：`/api/sensors/{sensorId}`

#### 2.3 请求体（Request Body）
- 用于 POST、PUT、PATCH 请求
- 使用 JSON 格式
- 示例：
```json
{
  "sensorId": "1234567890",
  "installationLocation": "办公室",
  "areaId": 1,
  "smokeThreshold": 80
}
```

### 3. 请求头（Request Headers）
| 头信息 | 描述 | 示例 |
|--------|------|------|
| Content-Type | 请求体格式 | application/json |
| Authorization | 认证信息 | Bearer token123456 |
| User-Agent | 客户端信息 | Mozilla/5.0 |

## 四、响应规范

### 1. 响应格式

#### 1.1 成功响应
```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "sensorId": "1234567890",
    "installationLocation": "办公室",
    "areaId": 1,
    "smokeThreshold": 80
  }
}
```

#### 1.2 分页响应
```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "list": [
      {
        "sensorId": "1234567890",
        "installationLocation": "办公室",
        "areaId": 1,
        "smokeThreshold": 80
      },
      {
        "sensorId": "0987654321",
        "installationLocation": "会议室",
        "areaId": 2,
        "smokeThreshold": 80
      }
    ],
    "total": 100,
    "page": 1,
    "size": 10,
    "pages": 10
  }
}
```

#### 1.3 失败响应
```json
{
  "code": 400,
  "msg": "参数错误",
  "data": null
}
```

### 2. 响应码（Code）

#### 2.1 系统响应码
| 响应码 | 描述 |
|--------|------|
| 200 | 操作成功 |
| 400 | 参数错误 |
| 401 | 未授权 |
| 403 | 禁止访问 |
| 404 | 资源不存在 |
| 500 | 服务器内部错误 |
| 503 | 服务不可用 |

#### 2.2 业务响应码
| 响应码 | 描述 |
|--------|------|
| 1001 | 传感器不存在 |
| 1002 | 传感器已存在 |
| 1003 | 区域不存在 |
| 1004 | 报警阈值超出范围 |
| 1005 | 通知额度不足 |

### 3. HTTP 状态码
| 状态码 | 描述 |
|--------|------|
| 200 | OK - 请求成功 |
| 201 | Created - 资源创建成功 |
| 204 | No Content - 请求成功但无响应体 |
| 400 | Bad Request - 请求参数错误 |
| 401 | Unauthorized - 未授权 |
| 403 | Forbidden - 禁止访问 |
| 404 | Not Found - 资源不存在 |
| 500 | Internal Server Error - 服务器内部错误 |

## 五、接口分类

### 1. 系统管理接口
- 用户管理
- 角色管理
- 权限管理
- 区域管理

### 2. 传感器管理接口
- 传感器列表
- 传感器详情
- 传感器添加
- 传感器修改
- 传感器删除
- 传感器状态查询

### 3. 报警管理接口
- 报警列表
- 报警详情
- 报警处理
- 报警统计

### 4. 阈值管理接口
- 阈值列表
- 阈值修改
- 阈值历史

### 5. 通知管理接口
- 通知模板管理
- 通知记录查询
- 通知额度查询

## 六、安全规范

### 1. 认证授权
- 使用 JWT 进行身份认证
- 实现基于角色的访问控制（RBAC）
- 敏感操作需要二次验证

### 2. 数据安全
- 传输数据使用 HTTPS 加密
- 敏感数据加密存储
- 防止 SQL 注入、XSS 攻击等

### 3. 接口限流
- 对接口进行限流保护
- 根据 IP、用户等维度进行限流
- 返回适当的限流提示信息

## 七、错误处理

### 1. 错误类型
- 参数错误：请求参数格式不正确或缺少必要参数
- 业务错误：违反业务规则（如传感器不存在）
- 系统错误：服务器内部错误

### 2. 错误信息
- 错误信息应清晰、准确，便于调试
- 包含错误码和错误描述
- 敏感信息不应出现在错误信息中

## 八、接口文档

### 1. 文档工具
- 使用 Swagger 或 SpringDoc 自动生成 API 文档
- 文档应包含接口描述、请求参数、响应格式等信息

- 本地环境：`http://localhost:8080/swagger-ui.html`
- 开发环境：`http://dev.iot-system.com/swagger-ui.html`
- 生产环境：`http://prod.iot-system.com/swagger-ui.html`

## 九、示例接口

### 1. 获取传感器列表
- URL：`/api/device/sensor/list`
- 方法：GET
- 请求参数：
  - areaId：区域ID（可选）
  - pageNum：页码（默认1）
  - pageSize：每页数量（默认10）
- 响应：
```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "list": [
      {
        "sensorId": "1234567890",
        "materialCode": "JTY-GD-TCN2010",
        "installationLocation": "办公室",
        "areaId": 1,
        "areaName": "一楼",
        "smokeThreshold": 80,
        "tempUpperLimit": 50,
        "tempLowerLimit": -10,
        "status": 1
      }
    ],
    "total": 100,
    "pageNum": 1,
    "pageSize": 10,
    "totalPage": 10
  }
}
```

### 2. 添加传感器
- URL：`/api/device/sensor/add`
- 方法：POST
- 请求体：
```json
{
  "sensorId": "1234567890",

  "installationLocation": "办公室",
  "areaId": 1,

  "tempUpperLimit": 50,
  "tempLowerLimit": -10
}
```
- 响应：
```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "sensorId": "1234567890",
    "materialCode": "JTY-GD-TCN2010",
    "installationLocation": "办公室",
    "areaId": 1,
    "areaName": "一楼",
    "smokeThreshold": 80,
    "tempUpperLimit": 50,
    "tempLowerLimit": -10,
    "status": 1

}
```

### 3. 获取传感器报警列表
- URL：`/api/alarm/list`
- 方法：GET
- 请求参数：
  - sensorId：传感器ID（可选）
  - startTime：开始时间（可选）
  - endTime：结束时间（可选）
  - pageNum：页码（默认1）
  - pageSize：每页数量（默认10）
- 响应：
```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "list": [
      {
        "id": 1,
        "sensorId": "1234567890",
        "alarmType": 1,
        "alarmTypeDesc": "火灾报警",
        "triggerTag": 1,
        "triggerValue": "烟雾浓度:120%",
        "alarmTime": "2023-06-01 12:00:00",
        "handleStatus": 0,
        "handleStatusDesc": "未处理"
      }
    ],
    "total": 50,
    "pageNum": 1,
    "pageSize": 10,
    "totalPage": 5
  }
}
```

### 4. 获取传感器参数
- URL：`/api/device/sensor/params`
- 方法：GET
- 请求参数：
  - sensorId：传感器ID（必填）
- 响应：
```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "sensorId": "1234567890",
    "smokeThreshold": 80,
    "tempUpperLimit": 50,
    "tempLowerLimit": -10,
    "batteryLevel": 90,
    "signalStrength": 85
  }
}
```

### 5. 配置传感器
- URL：`/api/sensor/config`
- 方法：POST
- 请求体：
```json
{
  "sensorId": "1234567890",
  "smokeThreshold": 85,

  "tempLowerLimit": -5
}
```
- 响应：
```json
{
  "code": 200,
  "msg": "配置成功",
  "data": null
}
```

### 6. 批量导入传感器
- URL：`/api/iot/device/batchImport`
- 方法：POST
- 请求参数：
  - file：Excel文件（必填）
- 响应：
```json
{
  "code": 200,
  "msg": "导入成功，共导入10条记录，成功8条，失败2条",
  "data": {
    "successCount": 8,
    "failCount": 2,
    "failList": [
      {
        "rowNum": 3,
        "message": "传感器已存在"
      },
      {
        "rowNum": 7,
        "message": "区域不存在"
      }
    ]
  }
}
```

### 7. 获取通知额度
- URL：`/api/notification/quota`
- 方法：GET
- 请求参数：
  - sensorId：传感器ID（可选）
- 响应：
```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "totalQuota": 1000,
    "usedQuota": 500,
    "remainingQuota": 500
```
