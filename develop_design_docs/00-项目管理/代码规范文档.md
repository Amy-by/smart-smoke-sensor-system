# 代码规范文档

## 一、文档说明

目的：规范智能烟感系统的代码编写风格和质量标准，确保代码的可读性、可维护性和一致性。

适用范围：所有参与智能烟感系统开发的团队成员。

## 二、前端代码规范（Vue3）

### 1. 命名规范

#### 1.1 文件命名
- 组件文件：使用 PascalCase 命名（如：`SensorAlarm.vue`）
- 工具文件：使用 camelCase 命名（如：`apiRequest.js`）
- 样式文件：与组件文件同名（如：`SensorAlarm.scss`）

#### 1.2 变量命名
- 普通变量：使用 camelCase 命名（如：`sensorId`）
- 常量：使用 UPPER_CASE 命名（如：`MAX_RETRY_COUNT`）
- 组件实例：使用 PascalCase 命名（如：`SensorAlarm`）

#### 1.3 函数命名
- 普通函数：使用 camelCase 命名（如：`getSensorData`）
- 事件处理函数：使用 `handle` 前缀（如：`handleAlarm`）
- 生命周期函数：使用 Vue 官方命名（如：`onMounted`）

### 2. 代码结构

#### 2.1 组件结构
```vue
<template>
  <!-- 模板内容 -->
</template>

<script setup>
// 导入语句
import { ref, reactive, onMounted } from 'vue'
import SensorApi from '@/api/sensor'

// 常量定义
const MAX_RETRY = 3

// 响应式数据
const sensorList = ref([])
const loading = ref(false)

// 计算属性
const filteredList = computed(() => {
  // 计算逻辑
})

// 函数定义
const getSensorData = async () => {
  loading.value = true
  try {
    const response = await SensorApi.list()
    sensorList.value = response.data
  } catch (error) {
    console.error('获取传感器数据失败:', error)
  } finally {
    loading.value = false
  }
}

// 事件处理
const handleSensorClick = (sensor) => {
  // 处理逻辑
}

// 生命周期
onMounted(() => {
  getSensorData()
})
</script>

<style scoped>
/* 样式定义 */
.sensor-list {
  /* 样式规则 */
}
</style>
```

#### 2.2 代码顺序
- 导入语句按模块类型分组（Vue 核心、组件、API、工具函数等）
- 常量定义在前，响应式数据在后
- 计算属性按功能相关性排序
- 函数定义按使用频率排序
- 生命周期钩子按执行顺序排列

### 3. 编码规范

#### 3.1 模板规范
- 使用 2 个空格缩进
- 组件属性换行时，每个属性占一行
- 使用 v-if/v-else 时，保持逻辑块连续
- 使用 v-for 时，必须添加 key 属性

#### 3.2 脚本规范
- 使用 Composition API（`<script setup>`）
- 避免使用全局变量
- 函数长度控制在 50 行以内，超过则拆分
- 使用 async/await 处理异步操作
- 合理使用 try/catch 捕获异常

#### 3.3 样式规范
- 使用 scoped 样式隔离组件样式
- 使用 BEM 命名规范（如：`sensor__item--active`）
- 避免使用 !important
- 使用 CSS 变量管理主题颜色

## 三、后端代码规范（Java Spring Boot）

### 1. 命名规范

#### 1.1 包命名
- 使用小写字母和点分隔（如：`com.iot.sensor`）
- 按功能模块组织包结构

#### 1.2 类命名
- 使用 PascalCase 命名（如：`SensorController`）
- 接口使用 `I` 前缀（如：`ISensorService`）
- 实现类使用 `Impl` 后缀（如：`SensorServiceImpl`）

#### 1.3 变量命名
- 普通变量：使用 camelCase 命名（如：`sensorId`）
- 常量：使用 UPPER_CASE 命名（如：`MAX_PAGE_SIZE`）
- 成员变量：使用 camelCase 命名，不加前缀

#### 1.4 方法命名
- 普通方法：使用 camelCase 命名（如：`getSensorById`）
- 控制器方法：使用 RESTful 风格命名（如：`getSensor`、`createSensor`）
- Service 方法：使用业务语义命名（如：`processAlarm`）

### 2. 代码结构

#### 2.1 类结构
```java
package com.iot.sensor.controller;

// 导入语句
import com.iot.common.result.Result;
import com.iot.sensor.domain.Sensor;
import com.iot.sensor.service.ISensorService;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.web.bind.annotation.*;

// 类注释
/**
 * 传感器控制器
 */
@RestController
@RequestMapping("/sensor")
public class SensorController {

    @Autowired
    private ISensorService sensorService;

    /**
     * 获取传感器列表
     * @return 传感器列表
     */
    @GetMapping("/list")
    public Result list() {
        return Result.success(sensorService.list());
    }

    /**
     * 获取传感器详情
     * @param sensorId 传感器ID
     * @return 传感器详情
     */
    @GetMapping("/{sensorId}")
    public Result getSensor(@PathVariable String sensorId) {
        return Result.success(sensorService.getById(sensorId));
    }

    /**
     * 创建传感器
     * @param sensor 传感器信息
     * @return 操作结果
     */
    @PostMapping
    public Result createSensor(@RequestBody Sensor sensor) {
        return Result.success(sensorService.save(sensor));
    }

    /**
     * 更新传感器
     * @param sensor 传感器信息
     * @return 操作结果
     */
    @PutMapping
    public Result updateSensor(@RequestBody Sensor sensor) {
        return Result.success(sensorService.updateById(sensor));
    }

    /**
     * 删除传感器
     * @param sensorId 传感器ID
     * @return 操作结果
     */
    @DeleteMapping("/{sensorId}")
    public Result deleteSensor(@PathVariable String sensorId) {
        return Result.success(sensorService.removeById(sensorId));
    }
}
```

#### 2.2 代码顺序
- 静态变量和常量
- 成员变量
- 构造方法
- 普通方法（按功能相关性排序）
- Getter 和 Setter 方法

### 3. 编码规范

#### 3.1 注释规范
- 类注释：使用 Javadoc 注释，说明类的功能
- 方法注释：使用 Javadoc 注释，说明方法的功能、参数和返回值
- 复杂逻辑注释：使用单行注释（//）说明关键逻辑

#### 3.2 异常处理
- 使用全局异常处理器处理通用异常
- 业务异常使用自定义异常类
- 捕获异常时，明确指定异常类型
- 异常信息应包含足够的诊断信息

#### 3.3 数据库操作
- 使用 MyBatis Plus 进行数据库操作
- 避免在循环中执行数据库操作
- 使用事务管理确保数据一致性
- 合理使用索引优化查询性能

#### 3.4 安全规范
- 避免 SQL 注入
- 验证所有用户输入
- 使用参数化查询
- 合理设置权限控制

## 四、通用规范

### 1. 代码格式
- 使用 4 个空格缩进（后端）或 2 个空格缩进（前端）
- 每行代码长度控制在 120 个字符以内
- 大括号使用 K&R 风格（同一行开始，下一行结束）
- 运算符两侧添加空格
- 逗号后添加空格

### 2. 代码质量
- 避免重复代码（DRY 原则）
- 保持函数单一职责
- 合理使用设计模式
- 避免过度设计

### 3. 测试规范
- 编写单元测试覆盖核心功能
- 测试方法命名清晰（如：`testGetSensorById`）
- 使用断言验证测试结果
- 保持测试的独立性

### 4. 文档规范
- 及时更新 API 文档
- 代码注释应解释 "为什么" 而不是 "是什么"
- 保持文档与代码的一致性
